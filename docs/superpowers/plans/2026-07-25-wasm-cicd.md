# Phase 5: WebAssembly & Cross-Platform Deployment — Plan

Design: `docs/superpowers/specs/2026-07-25-wasm-cicd-design.md`

## Task 1: Wall off `Avalonia.Desktop` from downstream consumers

`src/Chiaroscuro.UI/Chiaroscuro.UI.csproj`: add `PrivateAssets="All"` to the
`Avalonia.Desktop` `PackageReference`. No other change — this only affects
what flows to projects that reference `Chiaroscuro.UI`, not its own build.

Verify: `dotnet build Chiaroscuro.slnx -c Release` and `dotnet test
Chiaroscuro.slnx` both still pass unchanged.

## Task 2: Extract `MainView` from `MainWindow`

- New `src/Chiaroscuro.UI/Views/MainView.axaml` (+ `.axaml.cs`): a
  `UserControl` containing exactly the `<Grid>` currently inside
  `MainWindow.axaml`'s `<Window>` — a straight move, no binding/control
  changes. Drop window-only attributes (`Icon`/`Title`/`Width`/`Height`).
- `MainWindow.axaml` shrinks to a thin `<Window>` hosting
  `<views:MainView/>`, keeping `Icon`/`Title`/`Width`/`Height`.
  `MainWindow.axaml.cs` is untouched.
- `App.axaml.cs`: add an `else if (ApplicationLifetime is
  ISingleViewApplicationLifetime singleView)` branch that sets
  `singleView.MainView = new MainView { DataContext = new MainViewModel() }`,
  alongside the existing desktop branch.

Verify: build + full test suite still green (no test touches
`MainWindow`/`MainView` directly, so this is a behavior-preserving move as
far as tests can confirm; visual confirmation is manual, as with all prior UI
work in this project).

## Task 3: New `Chiaroscuro.Wasm` project

- `Chiaroscuro.Wasm.csproj`: SDK `Microsoft.NET.Sdk.WebAssembly`,
  `TargetFramework=net10.0-browser`, `OutputType=Exe`, `PackageReference
  Avalonia.Browser` pinned to `12.1.0` (match the rest of the repo's Avalonia
  packages), `ProjectReference` to `Chiaroscuro.UI`.
- `Program.cs`: its own `BuildAvaloniaApp() => AppBuilder.Configure<App>()`
  (do **not** reuse `Chiaroscuro.UI.Program.BuildAvaloniaApp()` — that one
  calls `.UsePlatformDetect()`, which needs `Avalonia.Desktop` and wouldn't
  pick the browser backend anyway). `Main` calls
  `BuildAvaloniaApp().WithInterFont().StartBrowserAppAsync("out")`.
- `Properties/AssemblyInfo.cs`: `[assembly: SupportedOSPlatform("browser")]`.
- `runtimeconfig.template.json`: standard Avalonia-browser host config
  (`wasmHostProperties.perHostConfig` → `{ name: "browser", host: "browser"
  }`).
- `wwwroot/index.html`: `<div id="out">` mount point matching
  `StartBrowserAppAsync("out")`, `<base href="/" />` as the first `<head>`
  child (rewritten by CI at deploy time, never hardcoded here), a loading
  splash styled with the app's existing palette (`#0C0A1D` background,
  `#FBBF24` text) instead of Avalonia's generic default.
- `wwwroot/main.js`: standard Avalonia-browser bootstrap glue (imports
  `./_framework/dotnet.js`, runs the main assembly) — copy from Avalonia's
  own template, nothing app-specific here.
- Add the new project to `Chiaroscuro.slnx` under `/src/`.

Verify: `dotnet build Chiaroscuro.slnx -c Release` succeeds (compiling
against `Avalonia.Browser`'s managed API doesn't need the `wasm-tools`
workload; only `publish` does — that's CI's job in Task 4).

## Task 4: CI workflows

**`.github/workflows/dotnet-ci.yml`** — matrix over `ubuntu-latest`
(`linux-x64`), `windows-latest` (`win-x64`), `macos-latest` (`osx-arm64` —
GitHub's macOS runners are Apple Silicon). Per OS: restore, build, `dotnet
test`, then `dotnet publish src/Chiaroscuro.UI/Chiaroscuro.UI.csproj -r
<rid> --self-contained true`, uploaded via `actions/upload-artifact`.
Triggers: push to `main` and pull requests. No Xvfb/headless setup needed —
confirmed no test instantiates a real Avalonia `Application`/`Window`.

**`.github/workflows/deploy-wasm.yml`** — single `ubuntu-latest` job,
triggers on push to `main` + `workflow_dispatch`. Steps: `dotnet workload
install wasm-tools`, `dotnet publish src/Chiaroscuro.Wasm/...`, rewrite
`<base href="/" />` in the published `index.html` to
`actions/configure-pages`'s `base_path` output (via `sed`), then
`actions/upload-pages-artifact` + `actions/deploy-pages`. Scoped
`permissions: pages: write, id-token: write` (kept off the desktop
workflow).

Note for the user: GitHub Pages must be switched to "Build and deployment:
GitHub Actions" once in the repo's Settings — a UI step I can't do myself.

## Verification (what's checkable here vs. deferred)

Locally checkable without the `wasm-tools` workload: `dotnet build
Chiaroscuro.slnx -c Release` (all 5 projects) and `dotnet test
Chiaroscuro.slnx` (existing suite, unaffected count/pass).

Deferred to CI's first real run: `dotnet publish` of `Chiaroscuro.Wasm`
actually succeeding, and whether Task 1's `PrivateAssets` fix is sufficient.
Deferred to the user: the deployed Pages URL actually rendering/orbiting
correctly in a browser, and the desktop binaries launching on real
Windows/macOS/Linux machines.
